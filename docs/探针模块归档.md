## 二、各模块的设计意图与判读逻辑

### 2.1 `text` —— 文字渲染定位（★ 交错设计）

**目的：** 定位"部分文字不渲染"的真正原因（症状是"文字凭空消失"而日志全对）。

**★ 关键设计：交错对照。** 每行放 3 个控件（编号 / 小字号 / 大字号），
行间有色带锚点。两组实验**每次只改一个变量**：

| 组 | 固定 | 变量 | 预期 |
|---|---|---|---|
| 第 1 组（行 g1~g3） | 字号 15px | 框高 | `h22`(比 1.47) 不显示 / `h28`(比 1.87) 显示 |
| 第 2 组（行 g4~g5） | 框高 42px | 字号 | `s20`(比 2.10) 显示 / `s30`(比 1.40) 不显示 |
| 第 3 组（行 g6） | —— | 基准 | `sm` 14px/26高 与 `lg` 30px/42高 |

**判读：**
- 第 1 组「h28 有、h22 无」→ 证实**框高决定显示**
- 第 2 组「s20 有、s30 无」→ 证实**比值决定，非字号绝对值**
  （这条**推翻**了"字号有上限"的猜测）

**★ 为什么必须交错（血泪教训）：** 早期用截图间距反推"哪一行显示了"，
**连续判错两次**，得出错误的"字号阈值"结论。改成交错设计后模式自证，
一次定位。**别用截图反推行号。**

**报告里还读回了 `adaptiveFontSize` / `minimumFontSize`**（只读不改）——
这两个字段是"字号自适应"相关，怀疑是文字消失的元凶。

### 2.2 `mask` —— 遮罩与裁剪

**目的：** 验证 `enableMask` 形状、`SetImage` 换图、矩形裁剪。

**★ 关键设计：父 200×100，子块 400×200（故意溢出 2 倍）。**
只有让子块明显超出，才能区分"被裁了"和"没裁"。

结构：
```
<div class="box" id="clip1">                 <!-- 裁剪窗口 200x100 -->
  <div style="width:400px;height:200px">     <!-- 子块 400x200，溢出 -->
</div>
<div class="sq" id="round1" style="border-radius:50%">  <!-- 圆形裁剪 -->
<div class="sq" id="shape1" data-image="1">  <!-- 形状图 -->
```

**`after()` 里用 `webui_clip.setImage` + `tint` 设置圆环/三角/圆形。**

**判读**（截图像素 = 画布 × 1.6）：
```
若【未裁剪】→ 子块应显示 ~640×320 px（完整 400×200）
若【被裁剪】→ 应限制在 ~320×160 px（父的 200×100）
实测 285×143 → 落在【被裁剪】区间 ✓
```

**★ 对照实验的重要性：** R17 里矩形图无效时，若没有圆图/三角图作对照，
就无法区分"这张图不适合"和"矩形裁剪做不到"。
**关键实验必须带对照组。**

### 2.3 `glyph` —— 几何字符与无缝方案

**目的：** 字符可用性 + 无缝方案对照。

结构：
```
<div class="line">●○■□◆◇▲△▼▽★☆</div>          <!-- 12 个字符 -->
<div class="line">✓✕→←↑↓│─┌┐└┘├┤┬┴┼</div>        <!-- 16 个框线字符 -->
<div class="line">■■■■■■■■</div>                  <!-- 连排测缝 -->
<div class="solid"></div>                          <!-- 纯色块，测无缝 -->
<div class="card"><div class="band"></div></div>   <!-- 矩形裁剪对照 -->
```

**判读：**
1. 第一行 12 个字符应全部显示为图形（**无豆腐块**）
2. 第二行 16 个框线/符号同理
3. `■■■■■■■■` 若有缝 = 比例字体（**已知 10px 缝，advance 1.59em**）
4. 纯色块应为**一整条无缝**（实测区间数 = 1）
5. 绿条应被卡片切到 260 宽（矩形裁剪）

**★ 一条重要的方法学约束：** **一个控件只验证一个方案。**
同一控件连写多个字符会互相覆盖，屏幕上只剩最后一个 —— R15 白跑过一轮。

### 2.4 `clip` —— 裁剪容器诊断

**目的：** 复现并定位两个真机异常
① 头像被拉伸（声明 130×130，实测宽高比 1.55）
② 矩形裁剪的色带溢出卡片边界

**★ 关键设计：四组对照，只差 `imageColor` 一个变量。**

| 组 | 配置 | 预期 |
|---|---|---|
| **A** | 遮罩容器**不设** `imageColor` | ❌ 白色月牙（白边） |
| **B** | `imageColor` **全透明** | ✅ 干净圆形 ← **库采用的做法** |
| **C** | `imageColor` **红色** | 边缘变红，**形状不变** |
| **D** | 矩形裁剪 + 透明 | 色带被切成 260 宽 |

**C 组的意义：** 证明 `imageColor` **只影响遮罩图的显示颜色，
不影响遮罩形状**。

**报告里逐控件打印** `sizeDelta` / `anchoredPosition` / `enableMask` / `imageId` ——
**探针必须读回实际值**，不能只打印"我打算设什么"。

### 2.5 `mount` —— mount 诊断

**目的：** `main.lua` 用 `webui.mount` 但**界面空白且无日志**时，
直接测出失败的真实原因，不靠猜。

**★ 逐个前提检查（6 步）：**

| 步 | 检查项 |
|---|---|
| [1] | `type(game)` / `typeof(game)` / `FindClientUIRoot` 是否存在 |
| [2] | `type(script)` / `typeof(script)` / `script.EnableUpdate` |
| [3] | `Enum` / `Color`；`rawget(Enum,'ImageSource')`；`Enum.ImageSource.StaticReference` |
| [4] | `FindClientUIRoot("Root")` + `GetClientUIRoots()` 列出全部根控件名 |
| [5] | **每个 prefab 索引能否真的建出控件**（返回 nil = 索引不存在） |
| [6] | **实跑一次 `mount`**，读 `app.bound`（必须是 `true`） |

**这条诊断直接推翻了两个错误假设：**
- `type(game)` 在真机上是 `table`（**不是** userdata）→
  "`type(game)=='table'` 短路"的假设不成立
- 界面空白的**真正根因**是「`OnUpdate` 不被驱动 + 模块 `_ENV` 身份」，
  见 §7.2

**★ 它是唯一"排障型"模块** —— 不做实验，只读回环境事实。
如果以后 `main.lua` 又出现"界面空白且无日志"，**优先重建这个模块**。

## 三、重建要点（重建时必须遵守）

从本文档重建任一模块时，务必守住这些（全部来自真机实测）：

| 约束 | 说明 |
|---|---|
| **探针必须读回实际值** | 早期探针只打印"我打算设什么"，误导了好几轮 |
| **一次只改一个变量** | 早期同时改父子嵌套+坐标+锚点，无法定位 |
| **关键实验必须带对照组** | 否则无法区分"这个方案不行"和"这个配置不对" |
| **别用截图反推行号** | R18~R19 连续判错两次；改用交错设计自证 |
| **一个控件只验证一个方案** | 同一控件连写多个字符会互相覆盖 |
| **新控件默认 `active=false`** | 不调 `SetActive(true)` 则完全不可见，但字段写入照常成功 |
| **`fontSize` 必须整数** | 浮点写入失败 |
| **枚举名禁止照文档猜** | 用 `pcall` 显式取并读回（R16 教训） |
| **截图像素 = 画布 × 1.6** | 2560 屏 / 1600 画布 |

**模块骨架**（`probe.lua` 的约定）：

```lua
M.<名字> = {}
M.<名字>.CSS = [[ <style>...</style> ]]      -- 可选，多数模块内联在 build 里
function M.<名字>.build() return ... end     -- 返回 HTML
function M.<名字>.after(ui) ... end          -- 可选，渲染后动作（如 SetImage）
M.<名字>.classes = { xxx = true }            -- 给 collect() 筛控件用
M.<名字>.report = function(ui, items) ... end -- 打印判读表
```

然后注册进 `MODULES` 表，并把 `ACTIVE` 改成模块名。
