# webui 未实现功能清单

> 2026-10-07 实测审计
> **更新：P0 批次已实现**（transform / z-index / :hover / :active / flex-grow / flex-shrink / flex-basis）

## 〇、本轮新增（已完成）

| 功能 | 状态 | 说明 |
|---|---|---|
| **`transform: translate`** | ✅ | `translate` / `translateX` / `translateY` → `anchoredPosition`（含 Y 轴翻转） |
| **`transform: scale`** | ✅ | `scale` / `scaleX` / `scaleY` → `localScaleX/Y` |
| **`transform: rotate`** | ✅ | `rotate` / `rotateZ`，支持 `deg` / `rad` / `turn` / `grad` |
| **`z-index`** | ✅ | 映射到 `SetSiblingIndex`，同父内排序 |
| **`:hover` / `:active`** | ✅ | 基于 `CursorEnter/Exit` + `CursorDown/Up` 维护状态 |
| **`flex-grow`** | ✅ | 按权重分配剩余空间 |
| **`flex-shrink`** | ✅ | 按 `shrink × 基础尺寸` 加权收缩 |
| **`flex-basis`** | ✅ | 优先于 `width` |

**已知限制：**
- `rotateX/Y`、`skew`、`matrix`、`perspective` **不支持**（引擎二维仿真），会被记录到 `style._transform.unsupported`
- `z-index` **只在同一父下生效** —— 引擎没有全局 z-index
- `:hover` / `:active` 的样式**会被 `node:setStyle()` 的运行时样式覆盖**（后者优先级最高，属预期行为）
- 伪类变化在**下一帧**生效（依赖 `flush()`）

---

## 一、引擎层面做不到（无解，需绕开）

这些不是库的问题，是千星客户端控件 API 的能力边界（真机实测确认）。

| 功能 | 原因 | 替代方案 |
|---|---|---|
| **自定义字体** | 无字体加载 API | 只能用默认字体 |
| **富文本** | 一个文本框只有一种样式 | 混排需拆成多个文本框 |
| **粗体/斜体** `font-weight` | 文本框无此字段 | 用字号或颜色区分 |
| **圆角** `border-radius` | 无边框渲染，只能靠图片。**6 个候选字段真机写入全部失败**（`写=false`） | 用图片控件（预配圆角图） |
| **边框** `border` | 同上 | 用 4 个细长色块拼，或用图片 |
| **阴影** `box-shadow` | 同上 | 用图片；`enableSoftEdge` 羽化可做柔边近似 |
| **任意路径绘制** | 无 canvas 类 API | **首选：图片控件 + `SetImage` 换形状图**（无缝、任意形状）；退路：字符（有缝） |

### 已解禁（原以为做不到，真机重测后可行）

| 能力 | 做法 |
|---|---|
| **矩形裁剪** `overflow:hidden` | 图片控件 + 矩形图当遮罩 + `enableMask`（R17 实证） |
| **任意形状裁剪** | 遮罩形状 = 图片 alpha，圆/三角/星/环均可 |
| **运行时换图** | `img:SetImage(Enum.ImageSource.StaticReference, id)`（R16 实证） |

### 4.1 几何图形：两种方案（★ 2026-10-07，R15+R16 真机验证）

**首选：图片控件 + `SetImage`**（R16 实证）

```lua
img:SetImage(Enum.ImageSource.StaticReference, 100002)   -- 圆形
img.imageColor = Color.FromRGBA(255, 200, 60, 255)       -- 染色
```

| 优势 | 说明 |
|---|---|
| **无缝** | 是图片，不经字体排版 |
| **形状任意** | 用户已有：方/圆/三角/四角星/五角星/圆环（ID 100001~100006） |
| **可运行时切换** | `SetImage` 实测 6/6 生效 |
| **可染色 + Tween** | `imageColor` |

> **能用图片就别用字符。** 字符是**没有图片资源时的退路**。

**退路：几何字符**（R15 实证可用，但有缝）

| 需求 | 用字符 |
|---|---|
| 状态点 / 图例 | `●` `○` |
| 方形标记 / 复选框 | `■` `□` |
| 菱形 / 装饰 | `◆` `◇` |
| 三角四向 | `▲` `△` `▼` `▽` |
| 评级 / 收藏 | `★` `☆` |
| 勾选 / 关闭 | `✓` `✕` |
| 方向 | `→` `←` `↑` `↓` |
| 框线 | `│` `─` `┌` `┐` `└` `┘` `├` `┤` `┬` `┴` `┼` |

**真机截图确认：全部渲染正常，无豆腐块。**
优势：不占 `image` 池、不用配资源。劣势：**必有缝**（见下）。

#### ★ 真机实测：字符**不能无缝拼接**（R15，2026-10-07）

两组独立实测，**advance 比例恒定**：

| 采样 | 字号 | 字形宽 | 缝 | advance | advance/字号 |
|---|---|---|---|---|---|
| 第 1 组 | 32 | 41px | 10px | 51px | **1.594** |
| 第 2 组 | 16 | 19px | 6px | 25px | **1.562** |

连排固定留缝 → **拼不出无缝长条**，且**缝随字号等比缩放，拉伸压不掉**。
单个 `■` bbox = **41×40px**，本身是正方形，但只能当**离散**图形。

> 注：本机 Windows 黑体测得的 `0.990em`（接近全角）**不能外推到引擎** ——
> 引擎实际是 1.59em。**字体度量必须真机实测。**

#### ★★ 无缝方案：纯色块 `bgColor`（两处独立实证）

| 方案 | 实测（截图像素） | 区间数 | 判定 |
|---|---|---|---|
| **A. 白色纯色块** | 宽 **478px** | **1** | ✅ **零断裂** |
| **D. 深色底条 + `●` 字符** | 宽 **477px** | **1** | ✅ **零断裂** |

**D 是推荐做法**：`bgColor` 做无缝底衬，字符 `fontColor` 叠加点缀 —— 两者都正常。

> 换算常数：**截图像素 = 画布单位 × 1.6**（2560 屏 / 1600 画布）。

#### 按「是否无缝」分工（★ 实践结论）

| 需求 | 方案 | 无缝？ |
|---|---|---|
| 长条 / 进度条 / 底衬 / 边框 | **文本框 `bgColor` 纯色块** | ✅ **实证无缝** |
| 底衬 + 字符点缀 | **`bgColor` 底条 + 字符 `fontColor`** | ✅ 底条无缝 |
| 状态点 / 星级 / 勾选 / 箭头 | **字符 + `fontColor`** | ❌ 有缝，但本就该离散 |
| 圆形 / 圆角 / 头像框 | 图片控件 + `enableMask` | ✅ 图片本身连续 |

**需要无缝的地方用纯色块更省更准；字符的价值在非矩形小图形。**

**何时仍必须用图片：**

- 圆角、边框、阴影（字符做不到）
- 超大尺寸图形（字符放大会露出字形边缘的锯齿）
- 需要非字符形状的图标（角色头像、技能图标等）

**精度注意：** 字符**不是**全角等宽，缝随字号等比变化（`@32` 为 10px）。
**别把字符当可平铺格子用**（详见 `引擎能力与限制.md` §4.2）。

> 详见 `引擎能力与限制.md` §4.2。
> 探针：`probe.lua`（模块 `glyph`）。

## 五、优先级建议

如果要继续完善，建议顺序：

**第 1 批（性价比最高）**
1. `transform: translate/scale/rotate` → 映射到已有字段，**改动小、用途广**
2. `z-index` → 映射 `SetSiblingIndex`，解决"元素被遮挡"问题
3. `:hover` / `:active` 伪类 → 事件系统已具备，补样式切换即可

**第 2 批（提升表现力）**
4. `flex-grow` → 让元素能自动撑满剩余空间
5. `transition` → 用 `game.Tween` 做平滑过渡
6. 文本换行改进 → 按单词边界断行

**第 3 批（特定场景）**
7. `flex-wrap` 多行
8. `text-overflow: ellipsis`
9. 圆角/边框的图片方案封装

## 六、明确不建议做的

| 项 | 原因 |
|---|---|
| **JS 解释器** | 无 `coroutine`，性价比极低 |
| **自定义字体** | 无 API |
| **格布局（CSS Grid）** | 投入大、客户端界面少用，flex 够 |
| **完整 CSS 规范** | 目标是"够用"，不是"完整" |
