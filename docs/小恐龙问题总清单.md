> 依据：git 历史 + 各文档的"踩坑"记录 + commit message，逐条对**当前代码**核实过；

## 一、库缺陷（LIB）—— 9 条

| # | 问题 | 症状 | 根因 | 修复 |
|---|---|---|---|---|
| L1 | **`__webuiParent` 用自定义字段存父子关系** | 每次操作全量新建 100+ 控件 → 越来越卡 → 崩溃 | 自定义字段真机**写不进去**，匹配永不成立 | 改用 `GetChildren()` 反查（`isChildOf`） |
| L2 | **按 `pairs()` 顺序压控件池** | 控件贴到错误父下 → 坐标错乱 / 界面消失 | 池是 LIFO，`pairs()` 顺序未定义 → 池序随机 | 按 DOM 先序**逆序**压池（`_order` 排序） |
| L3 | **`flex-direction:column` 忽略子项 `width`** | 圆被拉成**扁椭圆**；400px 色带够不到边界 | 布局器无条件把子项宽度设为父宽 | 修布局器 |
| L4 | **`intrinsicWidth` 重复计算 `margin`** | 容器比内容宽一个 margin → **白竖条** | 含 margin 后调用方又加一次 | 去掉重复累加 |
| L5 | **裁剪容器填充不受自身遮罩约束** | 圆外跑出**暗色月牙** | `enableMask` 只裁子控件，控件自身填充不受约束 | 裁剪容器一律 `imageColor` 全透明 |
| L6 | **遮罩图自身可见** | 裁剪边缘一圈**白边** | `SetImage` 后图会显示，而形状图是白色渐变 | 同上（`imageColor = (0,0,0,0)`） |
| L7 | **事件监听在控件复用时累积** | 一次点击触发 N 次；越用越卡（实测 40 次操作 → 989 次注册） | 还池时没清监听 | `_hide` 里 `RemoveAllCursorEventListeners` |
| L8 | **CSS `transition` 永不生效** | 颜色**直接跳变**，不是渐变 | `setStyle("background-color")` 标脏 → 清 diff 缓存 → `prev=nil` → `isFirst=true` → 不走过渡 | 清缓存时对**颜色字段保留 `prev`**（`KEEP_PREV`） |
| L9 | **复用控件继承上一个主人的外观** | 图片控件莫名是白的/红的；`textbox.text` 残留旧文案 | 还池只 `SetActive(false)`，外观字段一个不清 | `_take` 交付前 `_resetReused`（染色 → **全透明**） |

## 四、反复出现的模式（★ 这一节最重要）

单个 bug 修完就结束了，**下面这四条会继续咬人**。

### 模式 1：约束只写在文档里 → 必然复发（L10）

`_orphan` 的结论 10-07 就写在复盘里，10-07 当天代码就违反了它。
**文档拦不住任何人**（包括写文档的自己）。

> **对策：** 会被违反的约束必须变成**测试**。
> 现在 `test_pool_reset.lua` 用源码级断言守住它。

### 模式 2：测试替身不忠实 → 假绿（T1/T2/T3/T4，4 次）

每一次都表现为"本地全绿、真机出问题"，且**每次都浪费一轮以上的排查**。

> **对策：** mock 的每条"简化"都要问一句"真机是这样吗？"。
> 宁可让 mock 更麻烦，也不要让它更宽松。

### 模式 3：从一个场景的实测外推到另一个场景（2 次纯正 + 3 次同型）

**最典型的例子：** R16 实测 `imageColor` alpha=0 在**裁剪容器**下能做到"自身透明"，
R28 就外推到**普通图片控件**用来隐藏星月 —— 结果真机白天**仍然看得见星月**。

> 两次的语义根本不同：前者是"遮住遮罩图自身的白边"，后者是"普通控件调透明度"。
>
> **对策：** 换场景就要重测。**API 签名相同 ≠ 语义相同。**

同型的还有：
- 拿"第一阶段"的 `waveGap` 代表所有阶段（T5）
- 想"多跑一会儿"来验证阶段4（mock 里没有完美玩家，永远到不了）
- 用一轮 0 鸟就推断"出鸟率有问题"（7.5% 的概率本来就会发生）

### 模式 5：修复存在，但【没有测试真的守着它】（用突变测试发现）

**"所有测试全绿"不等于"修复被守住了"。** 想验证守卫是否真实，
只有一个可靠办法：**把修复故意改坏，看测试会不会红**（突变测试）。

对 9 个库缺陷的修复各做一次定向突变，结果：

| 突变（把修复改坏） | 结果 |
|---|---|
| 去掉 `_resetReused` 调用 | ✅ 变红（守住了） |
| `isOrphan` 恒返回 false | ✅ 变红 |
| `imageColor` 复位值改回白色 | ✅ 变红 |
| 去掉 `KEEP_PREV`（transition） | ✅ 变红 |
| 去掉还池清监听 | ✅ 变红 |
| 去掉 `isChildOf` 父匹配 | ✅ 变红 |
| **裁剪容器不再显式置透明** | ⚠️ **原本全绿** → 已补断言 |
| **flex row 多算一次 margin** | ⚠️ **原本全绿** → 已补断言 |
| **父链检查读 `__webuiParent`** | ⚠️ **原本永远通过** → 已改成 `GetChildren()` |
| 池内压入顺序（逆序→正序/排序失效） | 全绿 —— **但经核实这不是缺陷**（见下） |

**★ 三个真实缺口都已补上：**

1. **`test_clip` 的断言太宽松** —— 它接受 `nil`（从未写入）**或** `a==0`。
   但真机上 `nil` 是危险的：裁剪容器是 image 控件，会显示遮罩图（白→灰渐变），
   不置透明就在边缘**露白边**。现在只接受 `a == 0`（必须**显式**置透明）。

2. **`test_layout` 只守了 `intrinsicWidth` 本身**，没守"调用方会不会再加一次 margin"。
   把 flex row 的 `outerW` 改成多算一次 margin，整个套件仍全绿。
   已补断言：`rb.x == 前项宽 + margin`（若算两次会差 20px）。

3. **★ `test_parent` 的父链检查是【空检查】** —— 它读 `c.__webuiParent`，
   而那是**自定义字段**（真机写不进去，L10 的同型错误），
   该测试用的普通 table mock 恰好允许写它 =>
   **断言看起来在检查，实际只验证了 mock 自己的记账**。
   把 `isChildOf` 改成恒 `true`（完全不做父匹配），它照样全绿。
   已改成用 `GetChildren()` 反查（与库同一机制）。

**★ 一处旧说法的更正（mutations 全绿，但原因不是"没守卫"）：**

`webui_render.lua` 原先注释称"池内顺序必须 = DOM 先序逆序，否则同结构命不中"。
突变测试显示：逆序 / 正序 / 排序失效三种方式，
`created=20 reused=370` **完全相同**。

原因是 `_take` 会**遍历整个池**找父匹配控件，顺序只决定"选中哪个同父控件"，
而同父控件可互换。=> **顺序是"可预测性的优化"，不是正确性前提**；
真正必需的是 `isChildOf` 父匹配。注释已更正。

> **★ 通用启示：**
> 「测试全绿」只说明"没测出问题"，不说明"问题被守住了"。
> 想知道一条修复有没有守卫，就把它改坏试试 ——
> **改坏了还全绿，等于没有守卫。**

## 五、引擎客观限制（ENGINE）—— 不是 bug，要设计避开

| 限制 | 后果 | 应对 |
|---|---|---|
| **`onTick` 先于 `flush`** | 当帧新建的控件，在 `onTick` 里拿不到引用 → 贴图落空 | 每帧幂等补一次（`sprite.reassert`） |
| **自定义字段不可写** | 控件上存不了任何状态 | 存外部表 / `GetChildren()` / 库内账本 |
| **textbox 模板自带圆角（≥8px）** | 8px 色块变圆；88% 的矩形变形；也是"缝"的真凶 | 拼像素图**必须**用 image 控件 |
| **相邻矩形露 1.25~4.38px 缝** | 图形看起来是碎的 | 每个矩形四边外扩 1px（bleed） |
| **无 reparent API** | 控件固定在创建时的父下 | 复用必须匹配父 |
| **新控件 `active` 默认 `false`** | 不可见但字段写入"成功" | 取出后必须 `SetActive(true)` |
| **textbox 默认底色是深色** | 不写 `background-color` → 深色底 + 深色字 = **看不见** | 文字框必须显式写背景色 |
| **`OnUpdate` 不被驱动** | 逐帧要靠递归 `TweenSequence` | 库已封装 |

## 六、典型案例：白块（横跨全部五类）

白块问题最能说明"一个问题往往不是一类原因"，值得完整看一遍：

| 阶段 | 发现 | 类别 |
|---|---|---|
| R24 | 未 `SetImage` 的控件显示模板自带图（白→灰渐变） | ENGINE |
| R28 §8.7 | `sprite.apply` 只在"由隐藏变显示"时重贴图 → 漏染色 | **LIB** |
| R29 | 真正的根因：`onTick` 早于 `flush`，贴图发生在控件还不存在的当帧 | ENGINE |
| R29 | demo 加"每帧补帖图"绕过 | DEMO |
