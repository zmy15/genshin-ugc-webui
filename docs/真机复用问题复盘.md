## 二、根因：引擎控件**无法保存自定义字段**

### 探针证据（`probe_field.lua`，真机）

```
===== 自定义字段 =====
__webuiParent   写=false  读=true  值=nil
_order          写=false  读=true  值=nil
_orphan         写=false  读=true  值=nil
myCustomFlag    写=false  读=true  值=nil

===== 引擎预定义字段（对照）=====
bgColor         写=true   读=true  值=4294901760
text            写=true   读=true  值=K
fontSize        写=true   读=true  值=18

===== 父子关系 API =====
ROOT:GetChildren() 返回 1 个
测试控件是否为 ROOT 的子: true
```

**结论：控件（userdata）只允许写引擎预定义字段，自定义字段静默失败。**

### 导致的 bug

```lua
c.__webuiParent = parent          -- 静默失败，永远是 nil
if c.__webuiParent == parent then -- 永不成立
  ...复用...
end
```

复用永远失败 → **每次操作全量新建 100+ 控件** → 越来越卡 → 最终崩溃。

---

## 三、修复

### 1. 用 `GetChildren()` 反查父子（代替自定义字段）

```lua
local function isChildOf(ctrl, parentCtrl)
  if not ctrl or not parentCtrl then return false end
  local ok, kids = pcall(function() return parentCtrl:GetChildren() end)
  if not ok or type(kids) ~= "table" then return false end
  for i = 1, #kids do
    if kids[i] == ctrl then return true end
  end
  return false
end
```

### 2. 回收时按 DOM 先序逆序压池

```lua
-- style.apply 里赋序号
n._order = order

-- 预回收：按 _order 排序后【逆序】压入
table.sort(ordered, function(a,b) return a.node._order < b.node._order end)
for i = #ordered, 1, -1 do
  list[#list + 1] = ordered[i].entry.control
end
```

**为什么必须这样：** 池子是 LIFO（`table.remove` 取尾部）。若用 `pairs()` 遍历（Lua 顺序未定义），池子顺序随机 → 取到的控件父链错位 → 坐标错乱。

## 四、三轮迭代的完整脉络

| 轮次 | 做法 | 结果 |
|---|---|---|
| 1 | 要求 `__webuiParent` 精确匹配 | ❌ 雪崩新建（当时以为是"父匹配太严"） |
| 2 | 去掉父匹配，只按 kind 取 | ❌ 控件贴到已隐藏的旧父下 → 界面消失 |
| 3 | 恢复父匹配 + 按 DOM 序压池 | ❌ 仍雪崩（因为 `__webuiParent` 根本写不进） |
| 4 | **改用 `GetChildren()` + DOM 序压池** | ✅ **成功** |

**前 3 轮都在治标** —— 真正的问题不在"匹配策略"，而在**匹配依据（自定义字段）根本不存在**。

## 六、真机实测的能力约束（累积）

| 约束 | 证据 |
